## 一、最近用 Opus 5.5 做 3D 游戏的流程（10-31 01:37 查）
- **Tripo 官方《How to Make 3D Models with Claude Opus 5.5》（2026-10）：** 分工是 Tripo 生成模型、贴图、骨骼和动作；Opus 5.5 把文件拿进 Blender 检查、修骨骼和穿模、搭场景、打光、渲染。Opus 自己用代码建模只能做出粗模，人脸、手、头发、布料要靠 Tripo。Tripo 还有给 AI 用的命令行工具（`tripo-cli`），AI 可以直接调用 Tripo 生成模型（要 Tripo API 积分和 key）。来源：https://www.tripo3d.ai/blog/how-to-make-3d-models-with-claude-opus-5-5
- **他们的角色流程：** Tripo P2.0 生成（部件分开、四边面）→ Rig 选 Humanoid → Animate 选预设动作 → 导出 GLB 时勾上贴图和动画 → Blender 里检查骨骼、动作、贴图、脚是否贴地 → 修问题（例子里尾巴没有骨骼，被腿带着拉伸；裙子和头发穿过腿）。
- **Tripo《How to Animate an AI-Generated 3D Model》（2026-10）：** 自动绑骨最适合 T 字姿势的人形和标准站姿的四足动物；坐着、蹲着、手臂贴身、拿着道具都容易绑错。Auto Rig 每次 20 积分，绑好后从动作库选待机、走、跑、挥手等。动作库没有的，要用单独的 AI 动作捕捉工具。来源：https://www.tripo3d.ai/blog/how-to-animate-an-ai-generated-3d-model
- **一位独立开发者用 Opus 5.5 做完并上线了一个 3D 网页游戏（2026-10）：** 概念图用 GPT 的图像模型，3D 用 Tripo，声音用 ElevenLabs；AI 一共干了约 6.5 小时，用几个子助手并行做美术、场景和方块原型。来源：https://daily.dev/posts/i-built-and-shipped-a-3d-game-with-claude-opus-5-5-full-workflow--rj7lpd5tb
- **共同的做法：** 先出一套风格统一的概念图 → 列素材清单 → 生成 3D → AI 在 Blender 里检查和修 → 玩法用方块并行开发 → 换上素材 → 测试。小王子案例和 Tripo 官方 Playbook 也是这个顺序（见 [制作流程](制作流程.md)）。

## 二、要不要先用 GPT Image 2 出图
要，但只出有明确用处的图，而且**不用等图出完才写代码**：玩法代码不依赖最终素材，素材到了再换进去。

| 优先级 | 出什么 | 给谁用 | 为什么 |
|---|---|---|---|
| 1 | 六只怪物，每只一张 | Tripo → 游戏 | 现在一只怪的模型都没有，游戏里全是占位 |
| 1 | 三个主角的 **T 字姿势**四视图 | Tripo 重新生成 → 绑骨 → 游戏和 Unity | 现在的模型是双臂下垂，自动绑骨容易出错；可以顺便把黄色角色的头改成自己的设计 |
| 2 | 游戏画面概念图、冥界场景概念图 | Kiro、队友、Codex | 统一画面方向 |
| 2 | 界面用的 2D 图：游戏标题字、技能卡的金色画框、结局卡的画框、开始画面背景 | 直接放进网页 | GPT Image 2 擅长画带字的 2D 图，这类东西不用 3D |
| 3 | 结局卡上的名画 | 网页 | 用博物馆的公有领域原图，不用生成 |

**注意：** 发给 Kiro 或传进仓库的图，宽高都不能超过 2000 像素。

## 四、人物动作怎么设计
| 角色 | 游戏里要的动作 | 做法 |
|---|---|---|
| 三个主角 | 待机呼吸、跑、弹琴攻击（身前的琴发光，身体一顿）、受伤（闪红后仰）、倒下、胜利 | 先用代码做，保证能动；同时拿一个主角试 Tripo 自动绑骨，套上预设的待机和跑。效果好就换上，攻击和受伤仍用代码叠在上面 |
| 新娘 | 飘着跟在身后、回头时消散成光点、结局伸手 | 代码加粒子，不绑骨 |
| 亡魂等小怪（同屏几百只） | 飘、蹦、被打退、闪白、散成萤火 | 只能用代码。几百只同时做骨骼动画，手机扛不住 |
| 三头犬 Boss | 走、扑咬、睡着 | Tripo 四足自动绑骨加预设动作；不行就用代码 |
| Unity 过场 | 跪下、回头、伸手、拥抱 | Tripo 绑骨加预设或 Mixamo 动作。动作库没有的（比如"回头"），可以用赞助方 V2Fun：用手机拍一段自己演的视频，它从视频里提取动作，再套到角色上 |

**在游戏镜头下的取舍：** 主角在手机上只有拇指大小，看得出的是整体的弹跳、身体朝向和闪光，看不清手指和腿的细节。所以游戏里的动作重在"身体有节奏、打中有反馈"；精细的动作留给 Unity 过场的特写。

## 五、建议的顺序（现在 01:40，离提交约 16 小时）
1. 用户先在 Tripo 里拿**现有的兔子模型**试一次自动绑骨（约 20 积分），套"待机"和"跑"两个预设，导出带动画的 GLB 发给 Kiro。Kiro 检查能不能用、披风会不会扯坏。这一步决定要不要重做 T 字姿势的主角。

4. 绑骨效果好，再出主角的 T 字姿势四视图重做；不好就一直用代码动作。
5. 界面 2D 图和概念图有空再出。
