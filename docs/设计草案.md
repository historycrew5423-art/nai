## 一、用户定的（10-30 19:33，按原话整理）
- 类型：几个主角、多个皮肤、多种技能的打怪射击 3D 游戏。
- 杀怪之后换皮肤。
- 升级后变强，比如一颗子弹变成两颗，或者能从后面射出。
- 不同角色有不同的技能和操作。
- 怪物要特别多，多到一直要打，压力大。快打不完的时候突然升一级，从 3 个技能里抽一个，选好就能直接打爆一波怪。
- 横屏 16:9。手机网页，现场给观众链接玩。用户的手机是 iPhone。
- 小怪的模型由用户提供。
- 两人参赛。

## 二、启动会的新规定（用户转述）
- 可以找开源的场景、地图和源码来参考，但不能完全照搬换皮。
- 一定要路演，所以玩法要有意思。

## 三、核心循环
选角色 → 进场，怪从四面八方涌来，越来越多 → 开枪打怪，打死的怪掉经验 → 升级时画面变慢，三个技能选一个（子弹变两颗、往后射等）→ 坚持 2 分钟，最后来一个 Boss → 累计击杀数解锁新皮肤。

## 四、AI 建议加的（待确认）
"升级三选一、子弹变多、往后射"在手机上已经是很成熟的玩法。只做这些，评委会觉得眼熟，也可能碰到"与已上线产品极度相似"那条规则。下面几条用来拉开差别，建议先做 1 和 2，3 看时间。

1. **被围得越紧，升级越快。** 经验不只靠杀怪，身边的怪越多，经验涨得越快。选完技能的那一刻，以主角为中心炸开一圈，清掉身边一波怪。这样"快打不完时突然升级、一下打爆"就从碰运气变成每局都会发生。玩家还要自己赌：躲远一点更稳，还是让怪贴上来换更快的升级。
2. **怪潮会叠起来。** 怪挤不动时会爬到别的怪身上，堆成一堵墙压过来。这是只有 3D 才有的画面，投屏路演时好看，观众记得住。
3. **皮肤会改子弹。** 每款皮肤除了外观，子弹的样子和一个小特性也不同，比如穿透、冰冻。累计击杀数存在手机上，观众为了解锁下一款会再玩一局。

## 五、角色（待确认）
先做 3 个，每个操作都不一样：
- **A：** 只用一个摇杆走，自动瞄准开枪。最简单，给第一次玩的观众。
- **B：** 左手走，右手瞄准，伤害更高。
- **C：** 按住蓄力，松手打出一发能穿透的大炮。

每个角色另有一个自己的大招按钮。

## 七、开源素材
- 主角候选：带骨骼和动作的 CC0 人物包（CC0 即免费、可商用），比如 Quaternius、KayKit 这类。用之前逐个核对许可和动作。
- 每个素材的来源和许可写进 README，提交表上如实勾选。
- 玩法代码自己写，不套别人的游戏模板。

## 八、技术
- three.js 网页游戏，用 GitHub Pages 从 `dev` 分支发布，观众扫码就能玩。
- 同一种怪一次画完（实例化绘制），目标是 iPhone 上同屏 300 只以上不卡。今晚的方块版就在用户手机上实测。
- 怪不用骨骼，动作用代码做：蹦着走、被打退、闪白、炸开。

## 九、iPhone 和横屏
- iPhone 的 Safari 不允许网页强制横屏或全屏。竖着拿时画面显示"请横过来"；横屏后画面固定 16:9，多出来的地方留黑边。
- 观众要先关掉控制中心里的"竖排方向锁定"。横屏时 Safari 的地址栏会占一点地方；"添加到主屏幕"后再打开接近全屏，路演用这个方式。
- github.io 在国内一般能打开，但有时慢。第一版出来后，用户不开代理、用流量实测一次。慢的话再加一个备用网址。

## 十、小怪模型的要求

- 不用绑骨骼。

- 在 GitHub 网页上直接拖进仓库。模型到之前先用简单形状占位。
